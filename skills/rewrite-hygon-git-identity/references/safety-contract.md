# 安全约束

只要本 Skill 要修改 Git 历史，就必须遵守本约束。

## 检查范围

HYGON 默认策略拒绝以下 Commit 字段中大小写不敏感的 `sugon` 或 `rogon`：

- Author Name
- Author Email
- Committer Name
- Committer Email
- Commit Message，包括标题和正文

确定性自动规则必须保持窄范围：

- `@sugon.com` -> 相同用户名的 `@hygon.com`
- `@rogon.com` -> 相同用户名的 `@hygon.com`
- `@rogon.cn` -> 相同用户名的 `@hygon.com`
- 删除异常邮箱值两侧的 ASCII 或弯引号

禁止模糊替换或全仓字符串替换。Name、Message 和非标准邮箱必须针对原始 Commit SHA 和具体字段，审批完整旧值和完整新值。

## 必须保持不变的内容

除已审批元数据和因此失效的签名外，以下内容必须完全相同：

- 最终 Tree SHA
- 文件字节、路径、模式和符号链接目标
- Commit 数量和 Merge Commit 数量
- 父子拓扑
- Author 和 Committer 时间
- 未获批准的 Author/Committer 名字和邮箱
- 未获批准的 Commit Message 字节
- 签名以外的扩展 Commit Header
- 明确选定目标分支以外的全部 refs

被重写 Commit 的所有后代都会因 Parent SHA 改变而获得新 SHA，这是预期行为，必须记录在 `commit-map.txt`。

## 强制人工审批点

每个审批点都必须暂停并取得明确授权，禁止从前一次审批推断后续授权：

1. **冻结审批**：确认目标仓库、目标分支、维护窗口和远程 URL。
2. **变更审批**：确认精确邮箱映射 SHA256、精确替换 SHA256（如有）和预计签名丢失数。
3. **审核分支发布审批**：确认允许创建临时远程审核分支。
4. **正式替换审批**：严格验证和必要扫描通过后，确认分支名、冻结旧 Tip、验证新 Tip，以及允许强制替换正式分支。

第 4 次审批必须发生在审核之后，且必须是用户新的明确消息。禁止把临时分支发布和正式替换合并为一个无人值守命令。

## 冻结与竞态保护

暂停目标分支的直接 Push、PR Merge、自动 Merge 和机器人写入。如果当前 GitHub 套餐无法对私有仓库强制执行分支保护，则使用已通知全员的人工冻结。

克隆前记录远端 Tip，随后脚本必须证明：

- 两个独立 mirror 都等于冻结 Tip；
- 推送临时审核分支前，远端正式 Tip 仍等于冻结 Tip；
- 正式替换前，远端正式 Tip 仍等于冻结 Tip；
- 正式替换使用显式 `--force-with-lease=<ref>:<old-tip>`。

任何不一致都表示冻结期间出现了新的写入，必须停止且不得推送。

## 备份规则

使用新的工作目录并创建：

- 一份不修改的证据 mirror；
- 一份独立的重写 mirror；
- 一份重写前完整 Git bundle；
- refs 清单、基线和 SHA256 清单。

禁止重写日常工作 clone，禁止执行 `git push --mirror`。禁止把旧历史备份发布成远程分支或 Tag；bundle 只能在受控权限下离线保存。

## 签名规则

签名 Commit 的密码学签名覆盖其元数据和 Parent SHA。修改邮箱或 Parent SHA 后，旧签名不再有效，因此重写只能从受影响的签名 Commit 中移除签名。

重写前必须报告并审批精确的预计签名丢失数。验证必须证明：

- 移除签名数等于获批数量；
- 被重写 Commit 未保留无效签名；
- 未受影响 Commit 的签名对象逐字节相同。

实际丢失数与审批不一致时验证失败，禁止发布远程分支。

## 其他分支和 Tag

每次只重写选定的 `refs/heads/<branch>`。其他分支和 Tag 可能仍暴露旧身份，审计必须列出共享旧历史的 refs。

公开发布前，每个相关 ref 必须：

- 登记为不可发布；或
- 从待发布远端删除；或
- 在另一次明确审批的操作中重写。

禁止把旧历史分支 Merge 回已重写分支。

## 审核与正式替换

先把验证通过的新 Tip 推送到新的临时分支，例如：

```text
rewrite/<branch>-hygon-identity
```

该分支用于人工检查和仓库要求的扫描。普通 Pull Request Merge 无法替换正式分支的历史祖先链。

只有管理员在第 4 次审批后才能执行正式替换。替换完成后：

1. 验证远端正式 Tip；
2. 执行快速身份审计；
3. 解除分支冻结；
4. 通知开发者重新克隆；
5. 未合并工作使用经过审核的 `cherry-pick` 迁移，禁止 Merge 旧历史；
6. 关闭或重建基于旧历史的 PR。

## 停止条件

发生以下任一情况时，不得发布临时分支或执行正式替换：

- 映射存在歧义或尚未审核；
- 禁止字段仍未解决；
- Git 或 `git-filter-repo` 版本/校验值不符合要求；
- 签名丢失数与审批不一致；
- 新旧 Tree SHA 不一致；
- 未获批元数据或其他 refs 发生变化；
- 必要合规或质量扫描新增问题；
- 远端正式 Tip 与冻结 Tip 不一致；
- 缺少凭据或管理员授权。
